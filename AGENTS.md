# go-mem0

Unofficial Go client for the Mem0 Platform API, generated from the OpenAPI document Mem0 publishes. If you only want to use the client from an agent, read [.agents/skills/go-mem0/SKILL.md](.agents/skills/go-mem0/SKILL.md) instead; this file is about changing the code.

## Architecture

One generated package, `mem0`, at the module root, driven by `gen.go`:

`scripts/fetch-spec.sh` downloads `https://docs.mem0.ai/openapi.json` to `api/openapi.json` → oapi-codegen with `config.yaml` → `client.gen.go`.

The entire OpenAPI 3.0.1 document is generated, including deprecated endpoints. No spec patch is needed.

## Stack

- Go 1.26.10.
- oapi-codegen, pinned as a `tool` dependency in `go.mod`.
- Runtime: `github.com/oapi-codegen/runtime`.

## Layout

- `gen.go`, `config.yaml`, `client.gen.go`: the package.
- `client_test.go`, `example_test.go`: tests, including the README example.
- `scripts/`: spec download, lint and security scan scripts.
- `api/`: the downloaded spec, gitignored.
- `vendor/`: vendored dependencies, regenerated by `make dep`.

## Dev workflow

Everything runs in the `Dockerfile.dev` image. You need Docker and Make.

```bash
make dep       # go mod tidy + go mod vendor
make generate  # download the spec and regenerate
make lint      # shellcheck, shfmt, go fix, golangci-lint
make test      # go test -race
make sec       # gitleaks, govulncheck, semgrep
```

## Project-specific landmines

- Authentication is `Authorization: Token <key>`, set with `WithRequestEditorFn`. The generated client does not add it automatically.
- Preserve the trailing slashes in spec paths. The client builds them from the generated operation definitions.
- The `number` to `float64` mapping covers unformatted numbers. Explicit `format: float` fields remain `float32`.
- V1, V2 and V3 memory methods have different request and response shapes. Search V3 returns an object with `results`; Search V2 returns an array and is marked deprecated in the spec.
- Search V3 and List V3 filters must include at least one entity ID. Scope requests to the intended user, agent, app or run.
- `make generate` always downloads the current spec, so review the generated diff after regeneration.
- `.github/workflows/regen.yml` regenerates the client every day and releases the result. When the checks fail, Claude edits the repository to fix them, but a fix may not touch the paths listed under `fix_protected_paths` in that workflow: the workflows, the Makefile, `AGENTS.md`, `.agents/rules/`, the lint, security and spec download scripts and their configs. A problem that needs a change there fails the run and needs a manual fix.
